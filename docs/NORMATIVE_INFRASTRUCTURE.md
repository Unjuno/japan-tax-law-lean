# Normative queue and completion determination (Objective §1)

This branch replaces the article-counting queue with a **normative-unit** queue.
It changes only Python tooling and generated ledgers; no Lean file is modified.

## What changed

| file | role |
|---|---|
| `scripts/ci/normative_ids.py` | collision-free 64-hex ids binding law id, history/revision id, 本則/附則/別表 provision id (incl. Part/Chapter/Suppl. `AmendLawNum`/AppdxTable ordinal), 条/項/号/枝番号/別表セル, ordinal, norm type and source fragment digest |
| `scripts/ci/norm_decomposer.py` | splits pinned text into CONDITION / LEGAL_EFFECT / EXCEPTION / DEEMING / PRESUMPTION / DELEGATION / READING_SUBSTITUTION / REFERENCE / … units with exact character offsets; unclassifiable text is `UNCLASSIFIED`, `needs_review`, never dropped |
| `scripts/ci/dependency_parser.py` | resolves law **name** + article/paragraph/item + enforced revision/date; a bare 15-character id is only a `bare_id_only` hint and never a resolved dependency |
| `scripts/ci/task_state.py` | durable `data/task_state.json` + `data/verification_evidence.json`; status derived from evidence only; owner/blockers/artifacts/review survive regeneration; changed source → PARTIAL + revalidation blocker; disappeared unit → STALE |
| `scripts/ci/task_selector.py` | selects only unfinished, unowned units whose dependencies match an exact (law_id, article_no, enforcement_date) PROVED_SCOPE/FULLY_VERIFIED unit; legal review is not a filter |
| `scripts/ci/task_queue.py` | projects every decomposed unit of every pinned provision (本則/附則/別表セル) with source position, coverage audit, dependencies, obligations and derived status |
| `scripts/ci/article_obligations.py` | reports status counts from evidence; needle/file/theorem-name matches are not completion signals |
| `scripts/law_audit/phase_e/article_scope.py` | article/table-cell scoped diagnostic plus mechanical reconstruction counts; explicitly not a completion gate |
| `scripts/ci/completion_gate_adversary.py` | independent auditor with H/T/D/C/U findings; checks source rules AND inspects the durable evidence ledger for unsupported FULLY_VERIFIED claims, without importing the queue modules |
| `scripts/ci/lean_kernel_audit.py` | records a successful `lake build` + forbidden-proof scan as a NECESSARY_NOT_SUFFICIENT gate; never marks a unit verified |
| `scripts/ci/link_existing_proofs.py` | attaches genuine kernel evidence to pinned units whose needles (matched against the exact reconstructed unit span, not a display prefix) and compiled Lean artifacts exist; linked units become PARTIAL, never FULLY_VERIFIED |
| `scripts/ci/coordinator_cycle.py` | one High4 SELECT→SOURCE-audit→VERIFY cycle; assigns and releases ownership, checks each selected unit's pinned hash, structural path, offsets and span digest, and records H/T/D/C/U findings; source-position only, no proof or completion claim |
| `scripts/ci/run_python_gates.py` | mandatory gate set; absent mandatory gate = FAIL; SKIP never counted as PASS |

## Status vocabulary

`NOT_STARTED / PARTIAL / PROVED_SCOPE / FULLY_VERIFIED / BLOCKED / STALE`.

`FULLY_VERIFIED` requires a **recorded evidence record with a non-empty
evidence reference** for all ten mechanical axes (plus `PROOF_CROSS_LAW` when
resolved dependencies exist), no unresolved condition and no blocker. Human
legal review (`LEGAL_REVIEW_PENDING`) is a separate axis; it never blocks
technical work and is required only for a global completion claim.

The article-scope / coverage audit answers only: *were the original characters
reconstructed and position-matched?* It reports
`MECHANICAL_COVERAGE_ONLY_NOT_SEMANTIC_AUDIT`; it does not assert that the
specification faithfully represents the statute. That requires the independent
`SOURCE_CORRESPONDENCE_AUDIT` and `ADVERSARIAL_REVIEW` evidence axes.

## Persistence and resume

* `build/task_queue.json` is a derived projection (git-ignored, 268,107 units
  across 62,981 provisions for the 2026-11-15 snapshot).
* `data/task_state.json` keeps only units with durable content; regeneration is
  non-destructive and atomic.
* `data/verification_evidence.json` is append-only evidence; every record needs
  an evidence reference.

To resume: `python scripts/ci/task_queue.py` then
`python scripts/ci/task_selector.py <n>`. Ownership is assigned by editing
`data/task_state.json` (`owner` field); the selector skips owned units.

## Measured state on this branch (2026-11-15 snapshot)

Generated by the gates; see `docs/TASK_QUEUE.md`, `docs/ARTICLE_OBLIGATIONS.md`
and `docs/ARTICLE_SCOPE.md` for the current measured values. All registered
Python gates pass with `SKIP=0` (26/26 at last full run). Lean build is executed
by `leanprover/lean-action` in CI; no `.lean` file was changed, so the existing
518-job kernel build and its proofs are carried forward unchanged.

Measured after evidence linking: **265,003 NOT_STARTED / 3,104 PARTIAL /
0 FULLY_VERIFIED**. The linked units carry evidence records from the pinned
needle audit (matched against exact reconstructed spans) and the successful
kernel build; they still lack DECOMPOSITION_AUDIT, PROOF_SCOPE, PROOF_BOUNDARY
and ADVERSARIAL_REVIEW, so no completion is claimed.

A first coordinator cycle selected 5 units and independently confirmed all 5
source positions (pinned SHA-256, structural path, offsets and span digest).
An initial FAIL was traced to a full-text cache keyed only by provision path —
two units in one provision reused the first slice — and fixed by including the
span offsets in the cache key; all 5 then passed. This is a source-position
check only (`SOURCE_POSITION_ONLY_NOT_LEGAL_VERIFICATION`).

This is **not** a claim that all Japanese tax law is verified. Unresolved
fragments, delegated facts, unenforced revisions and human legal review remain
explicitly open.
